Propenu Notification Testing Guide

Backend + Firebase push + admin campaign notification process

User Service Property Service Firebase FCM Postman Testing Admin Campaigns

1. What Was Implemented

The notification work now has two paths: automatic event notifications and admin campaign notifications.

Automatic Event Notifications

These are sent by backend business events. The implementation sends push notifications to the property owner or project builder, and also records/sends admin alerts.

Event Who receives push Where it is triggered
Buyer/user contacts a property owner Owner/builder/agent who owns the property, plus admins property-service/src/services/leadService.ts
Public featured project lead is submitted Project builder, plus admins property-service/src/services/publicLeadService.ts
User downloads a featured project brochure Project builder, plus admins property-service/src/controller/leadController.ts

Admin Campaign Notifications

Admins can send festival, offer, announcement, or general push notifications with text and optional image.

Audience Backend target Use case
all Every active user with a valid fcmToken General festival wishes or platform-wide announcement
builder Users with builder role Builder plan offers, project promotions, builder updates
agent Users with agent role Agent offers, lead updates, sales campaigns
owner Users with normal user role Owner property boost, property posting reminders
user Users with normal user role Buyer/renter messages, property recommendations, festival offers

2. Backend Routes Added Or Used

Route Method Purpose
/api/users/notifications/save-fcm-token POST Saves a user's Firebase device token.
/api/users/notifications/admin/notify/custom POST Admin sends campaign push notification with filters and optional image.
/api/users/notifications/admin/feed GET Admin reads automatic alerts plus sent campaigns.
/api/users/notifications/admin/feed/seen POST Marks admin notification feed as seen.
/api/properties/leads POST Creates contact-owner lead and sends automatic push.
/api/properties/leads/project/lead POST Creates public featured-project lead and sends automatic push.
/api/properties/leads/project/:projectId/brochure-download POST Tracks brochure download and sends automatic push.

3. Required Setup Before Testing

  1. Start backend services: gateway, user-service, property-service. Firebase push testing needs user-service and property-service connected to the same Mongo database.
  2. Make sure Firebase service account JSON exists and FIREBASE_KEY_PATH points to it.
  3. Make sure the target account has a valid Firebase fcmToken.
  4. Use an admin or super admin JWT for admin campaign routes.
Important: FCM push cannot be tested with a fake token. You need a real token generated by the frontend/mobile Firebase SDK.

4. Base URLs For Postman

If testing through gateway, use:

http://localhost:4000

If testing user-service directly, use:

http://localhost:4004

If testing property-service directly, use:

http://localhost:4003

The examples below use the gateway base URL.

5. Postman Authentication

For protected routes, add this header:

Authorization: Bearer YOUR_ADMIN_OR_USER_TOKEN

For admin campaign routes, the token must belong to a user whose role is admin or super_admin.

6. Save FCM Token

Before sending any push, save the target user's FCM token.

POST http://localhost:4000/api/users/notifications/save-fcm-token
Content-Type: application/json
{
  "userId": "TARGET_USER_ID",
  "token": "REAL_FIREBASE_FCM_TOKEN"
}

Expected response:

{
  "message": "Token saved"
}
Recommended first test: save the token for your own account, then send an audience=all campaign without image.

15. Test Automatic Notification: Contact Owner

This tests the automatic notification sent when a user contacts a property owner.

Requirements:

  • The buyer/user must be logged in.
  • The property must not belong to the same user.
  • The property owner/builder/agent must have a saved fcmToken.
  • For normal properties, buyer/renter subscription checks still apply.
POST http://localhost:4000/api/properties/leads
Authorization: Bearer BUYER_USER_TOKEN
Content-Type: application/json
{
  "name": "Test Buyer",
  "phone": "9876543210",
  "email": "buyer@example.com",
  "projectId": "PROPERTY_ID",
  "propertyType": "residentials",
  "remarks": "I am interested"
}

Supported propertyType values:

featuredprojects
residentials
commercials
agriculturals
landplots

New Contact Request

20. Common Errors And Fixes

Error Meaning Fix
403 Forbidden The JWT user is not admin/super_admin. Login with admin or super_admin account.
No users found No active users matched the audience/location filters with FCM token. Check role, city/state/locality spelling, and saved token.
No valid tokens Matching users exist but do not have fcmToken. Call save-fcm-token first with a real Firebase token.
Firebase service account file NOT FOUND Firebase Admin cannot find the service account JSON. Set FIREBASE_KEY_PATH correctly and restart backend.
messaging/registration-token-not-registered The FCM token is expired or invalid. Generate a fresh frontend token and save it again.
This is your own property User tried to contact their own property. Use a different user account as buyer/renter.

21. Quick Test Checklist

  1. Start gateway, user-service, and property-service.
  2. Confirm Firebase service account file path.
  3. Login as admin and copy JWT.
  4. Save a real FCM token for at least one target user.
  5. Send admin campaign with audience=all.
  6. Check device/browser push received.
  7. Check GET /api/users/notifications/admin/feed.
  8. Test builder/agent/owner filters.
  9. Test brochure download automatic notification.
  10. Test contact-owner automatic notification.
